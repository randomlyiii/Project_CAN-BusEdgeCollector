阶段一面试问题总结（10个）

1. CAN 主从站不共地导致通信失败
   现象：主站 TEC/REC=0，RX=0，CAN 完全不通。
   原因：CAN_H/CAN_L 是差分信号，但 ISO1050/TJA1050 收发器的共模电压范围（-7V~+12V）要求两端 GND 有公共参考。主从站各自独立供电时若 GND 未连通，共模电压可能漂出范围，收发器无法正确识别总线电平。
   解决：主从站 GND 之间拉一根杜邦线连通。
   延伸：工业现场长距离 CAN，建议用隔离收发器（如 ISO1050）+ 独立隔离电源，单点接地。

2. CAN 中断单缓冲覆盖导致心跳帧丢失
   现象：从站每 500ms 背靠背发送心跳帧+温湿度帧各一帧，主站心跳计数偶尔才 +1，温湿度帧正常。
   原因：STM32 CAN 有 3 级硬件 FIFO，但 ISR 中只用 `CAN_Receive(CAN1, CAN_FIFO0, &RxMsg)` 读一次。若两帧在同一中断间隔内到达（间隔 < ISR 执行时间），第二帧会留在 FIFO 中未被处理，下次中断来时才读——但中间可能被新帧覆盖。心跳帧先发、温湿度帧后发，心跳帧更早进入 FIFO 反而更容易被"压底"。
   解决：ISR 内改为 `while(CAN_MessagePending(CAN1, CAN_FIFO0))` 循环读空 FIFO，每帧用栈局部变量暂存再分发处理。
   关键认知：中断里"只读一次"是常见陷阱，FIFO 设计就是为了缓冲多次事件，ISR 必须负责 drain。

3. W5500 以太网驱动三合一故障（RST/MISO/SPI帧格式）
   现象：OLED 显示 IP:0.0.0.0 + ETH:FAIL，Modbus 无法连接。
   根因有三个独立问题叠加：
     a) RST 引脚错配为 PA3，实际 W5500 复位脚是 PC15 → 芯片一直处于复位状态
     b) MISO 配置为 GPIO_Mode_IN_FLOATING，而 STM32 SPI 全双工要求所有 SPI 引脚均为 AF_PP → 主机收不到从机数据
     c) SPI 帧格式错误：W5500 通过 BSB（Block Select Bits）+ 16 位地址间接访问寄存器，地址阶段需嵌入 BSB 位 → 帧格式不匹配，芯片不识别命令
   解决：参考已验证的 Project_template 驱动模板，逐项对比并修正。
   教训：100+ 寄存器、BSB 间接寻址的复杂外设（W5500），不应从零手写驱动，应从厂家 SDK 或已验证模板开始改。Vibe coding 在这类场景下缺乏硬件调试闭环，无法替代示波器抓波形和寄存器级验证。

4. W5500 模块供电不稳定（LDO 压差不足）
   现象：W5500 模块间歇性不工作，SPI 通信时断时续。
   原因：模块使用 5V→3.3V 板载 LDO。USB 供电实际电压约 4.6~4.8V，某些劣质模块 LDO 压差不够（如 AMS1117 需要 ≥1.1V 压差），3.3V 输出偏低导致 W5500 复位异常或内部 PHY 工作不稳定。
   解决：外接独立 3.3V 电源直接给模块供电（绕过板载LDO），或更换质量好的模块。同时确认模块两个 GND 引脚（逻辑地+功率地）都接地。

5. OLED I2C 推挽模式烧毁硬件
   现象：OLED 闪一下后永久不亮，换模块恢复。
   原因：为追求速度将 I2C SDA 引脚配置为推挽输出（GPIO_Mode_Out_PP）。I2C 协议要求 SDA 是双向信号——主机发送数据时驱动 SDA，从机应答 ACK 时也驱动 SDA。推挽模式下 ACK 位主从同时驱动 SDA 到相反电平，形成短路电流，烧毁 IO 口或从机芯片。
   解决：SDA/SCL 必须配置为开漏输出（GPIO_Mode_Out_OD），依赖外部上拉电阻（模块自带上拉）实现高电平。I2C 标准速率 100/400kHz，72MHz MCU 软件 I2C 需在 GPIO 翻转间加 ~2μs 延时。
   教训：协议物理层特性（开漏 vs 推挽）不能随意改，错了不是功能问题而是硬件损坏问题。

6. SysTick 被 Delay_us() 破坏导致系统卡死
   现象：OLED 上电闪一下后熄灭，整个系统不再运行。
   原因：软件 I2C 的微秒延时函数 Delay_us() 直接操作 SysTick->CTRL 寄存器实现短延时，退出时写死 CTRL=0x04（关闭中断），导致 SysTick 中断永久停摆。HAL 库和 OLED 刷新都依赖 SysTick 节拍，中断一停所有定时任务全部停止。
   解决：Delay_us() 入口保存 SysTick->CTRL 原始值，退出时恢复而非写死常量。
   知识点：CMSIS 已有 SysTick_Config() 初始化，裸机延时不要覆盖系统配置；如需微秒延时，用 DWT 计数器（CYCCNT）或定时器，不碰 SysTick。

7. sprintf 触发半主机模式导致 HardFault
   现象：调用 sprintf 格式化 OLED 显示字符串时程序崩溃进 HardFault。
   原因：ARM 工具链默认启用半主机（semihosting），sprintf 等标准库函数底层通过 BKPT 指令与调试器通信实现 I/O。无调试器连接时 BKPT 触发 HardFault。
   解决：在项目中添加 `#pragma import(__use_no_semihosting_swi)` 禁用半主机，或实现 `_sys_exit()` / `__user_initial_stackheap()` 等桩函数，确保标准库不依赖调试器 I/O 路径。
   延伸：FreeRTOS 环境下 sprintf 还会导致栈溢出（阶段二问题），因为 sprintf 栈消耗大（~200-300 字节），任务栈需至少 512 字节。

8. DHT11 重复读取导致主循环永久卡死
   现象：OLED 显示一次温湿度后整个界面卡死。
   原因：DHT11 的读取函数用 `while(IO_read && timeout--)` 轮询传感器应答信号。传感器要求两次读取间隔 ≥1s，但 OLED 刷新函数和主循环各调用了一次读取，间隔 <1s 时传感器不应答，while 循环等不到电平变化且 timeout 值太小（255次 ≈ 12μs << DHT11 80μs 应答），直接死循环。
   解决：① 主循环 2s 只读一次 DHT11，OLED 刷新只读缓存值；② 超时计数器从 255 加大到 5000+。
   教训：嵌入式 while 轮询必须有可靠超时退出机制；传感器时序约束（DHT11 1s 冷却期）必须在软件架构层面保证。

9. Modbus TCP 响应帧数据偏移 1 字节
   现象：OLED 显示温湿度正确（25.3°C, 62.1%），Modbus Poll 读到乱码（1, 2818, 29440, -27000）。
   原因：Modbus TCP 帧结构 = MBAP头(7字节) + 功能码(1) + 数据。请求解析用 PDU_DATA_IDX=10 定位到数据起始字节。响应帧构建时复用了同一个偏移常量，但响应帧从 byte 9（MBAP(7)+FC(1)+bytecount(1)=9）就该开始写数据，偏移 1 字节导致所有寄存器值错位读出。
   解决：新增 RESP_DATA_IDX=9 常量，请求/响应使用各自的偏移。
   教训：协议栈中"魔数"常量必须有明确命名和注释说明其语义边界，请求和响应帧结构不同时不能共用偏移量。

10. ST-Link 接线错误导致电源对顶
   现象：ST-Link 接了 SWDIO/SWCLK/GND/3.3V 四根线到蓝 Pill 开发板，电脑 USB 口闪屏、设备反复枚举。
   原因：ST-Link 的 3.3V 引脚会向目标板供电，而蓝 Pill 同时通过 USB 口供电，两路 3.3V 电源未经隔离直接对顶。轻则供电不稳、重则烧 USB 口或 ST-Link。
   解决：ST-Link 只接 SWDIO/SWCLK/GND 三根线，目标板由 USB 独立供电。
   补充：BOOT0 跳线必须拨到 0（GND），BOOT0=1 时芯片上电进入系统存储器启动模式（Bootloader），不运行用户 Flash 程序。
