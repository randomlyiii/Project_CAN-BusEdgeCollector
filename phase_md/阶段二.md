# 阶段二：FreeRTOS实时内核 + 双FIFO缓冲 + 工业级可靠性增强

## 阶段目标

在阶段一（裸机 CAN 基础通信 + Modbus TCP + OLED 验证）已完成的基础上，引入 FreeRTOS 实时操作系统，实现双 FIFO 缓冲架构、报文升降级机制、总线负载自适应限流、CAN 错误分级处置、Modbus TCP 断网缓存增强、从站光敏传感器采集与本地容错缓存，将原型验证系统升级为**工业级抗干扰数据采集终端**。

## 二、FreeRTOS 迁移（核心架构变更）

### 2.1 为什么需要 FreeRTOS

阶段一的裸机 `while(1)` 主循环存在以下问题：
1. **任务饥饿**：W5500 TCP 轮询阻塞时，CAN 心跳检测被推迟
2. **优先级缺失**：紧急帧处理与低频光敏帧在同一循环中平权竞争
3. **无抢占能力**：Modbus TCP 大数据包处理期间，CAN Bus-Off 复位无法立即执行
4. **扩展性瓶颈**：后续添加光敏、4-20mA、缓存管理等模块会导致主循环不可控膨胀

### 2.2 任务分解与优先级

按照 README 设计，数字越大优先级越高（使用 FreeRTOS `configMAX_PRIORITIES=8`）：

| 任务 | 优先级 | 栈深度 | 周期/触发方式 | 核心职责 |
|---|---|---|---|---|
| `vTask_CAN_Rx` | 5 (最高) | 256 | 中断信号量唤醒 | CAN Rx FIFO 读取 → 帧分类 → 写入双 FIFO |
| `vTask_CAN_Monitor` | 4 | 256 | 100ms 周期 | 总线负载率、TEC/REC、错误状态机、升降级裁决 |
| `vTask_CAN_Tx` | 3 | 256 | FIFO 非空信号量唤醒 | 从双 FIFO 取帧 → 优先级排序 → CAN 发送 |
| `vTask_Protocol` | 2 | 512 | 50ms 周期 | CAN ↔ Modbus 协议转换、寄存器同步 |
| `vTask_W5500` | 1 | 512 | 事件驱动 | W5500 TCP Server 轮询、Modbus 请求/响应 |
| `vTask_Housekeep` | 0 (最低) | 256 | 1s 周期 | 看门狗喂狗、故障日志存储、内存/栈监控、系统参数持久化 |

> **优先级说明**：`vTask_CAN_Rx` 优先级最高（5），确保 CAN 硬件 FIFO 不会溢出丢失紧急帧。`vTask_CAN_Monitor` 次之（4），保证总线状态检测及时触发限流/降级。`vTask_W5500` 优先级最低（1），因为以太网延迟容忍度远高于 CAN 实时性。

### 2.3 中断服务程序改造

阶段一中 CAN Rx 中断 (`USB_LP_CAN1_RX0_IRQHandler`) 直接在 ISR 内处理帧，阶段二改为：

```
ISR 内:
  1. 读取 CAN 帧到临时变量（50μs 内完成）
  2. 发送 Binary Semaphore 唤醒 vTask_CAN_Rx
  3. 清除中断标志，退出 ISR

vTask_CAN_Rx 任务内:
  1. 等待信号量（阻塞）
  2. 帧分类：Byte[0]=0 → FIFO_HIGH, Byte[0]=1/2 → FIFO_NORMAL
  3. 执行升降级规则（见第三章）
  4. 写入对应 FIFO（带互斥锁）
```

### 2.4 FreeRTOS 配置要点

- `configCPU_CLOCK_HZ = 72000000`
- `configTICK_RATE_HZ = 1000`（1ms 节拍）
- `configTOTAL_HEAP_SIZE = 15 * 1024`（15KB 堆，6个任务 + 队列 + 信号量）
- `configUSE_MUTEXES = 1`
- `configUSE_COUNTING_SEMAPHORES = 1`
- 使用 `heap_4.c`（支持碎片合并）
- SysTick 同时用于 FreeRTOS 心跳 + Delay 微秒级延时（与阶段一 I2C 延时函数兼容）

## 三、双 FIFO 缓冲架构

### 3.1 数据结构设计

```c
#define FIFO_HIGH_DEPTH   16   // 0级紧急帧专用
#define FIFO_NORMAL_DEPTH 64   // 1/2级常态+低频共用

typedef struct {
    CanRxFrame   buffer[FIFO_HIGH_DEPTH];
    uint8_t      head, tail, count;
    SemaphoreHandle_t mutex;
} CAN_FIFO;

typedef struct {
    CanRxFrame   buffer[FIFO_NORMAL_DEPTH];
    uint8_t      head, tail, count;
    SemaphoreHandle_t mutex;
} CAN_NormalFIFO;
```

### 3.2 溢出处置策略

| FIFO | 溢出条件 | 处置动作 |
|---|---|---|
| FIFO_HIGH | count == 16 | **丢弃最旧紧急帧**（head 前移），记录 `fifo_high_overflow_cnt++`，上位机可读该寄存器 |
| FIFO_NORMAL | count == 64 | **优先丢弃最新 2 级低频帧**（反向扫描 tail 找到 Byte[0]==2 的帧并覆盖）；若全部是 1 级，则丢弃最旧帧 |

### 3.3 并发保护

所有 FIFO 读写操作必须持有互斥锁（`xSemaphoreTake(mutex, pdMS_TO_TICKS(5))`），超时 5ms 视为获取失败，记录 `mutex_timeout_cnt` 供诊断。

### 3.4 主站 OLED 双页显示

主站新增 KEY 切页键（**PA0→GND**），可在两页显示间切换：

**Page 1 — 传感器 + 以太网：**
```
Line 1: "CAN:OK  ETH:CON "    // CAN错误等级 + W5500连接状态
Line 2: "S1:27.3C L:610   "   // 从站1温度 + BH1750光照（<1000 显示 lux）
Line 3: "H:65.0% HB:12345 "   // 湿度 + 心跳计数
Line 4: "R12.3K OK 15/64  "   // CAN帧总数 + 节点状态 + FIFO_H/N
```

- 光感 lux ≥ 1000 自动切换为 k-lux：`L:1.2k` / `L:65.5k`
- 总线负载原在 Page 1（`L:50.00%`）已移至 Page 2

**Page 2 — CAN 总线 + 报警：**
```
Line 1: "CAN:ERR L:12.50%"   // CAN错误等级 + 总线负载率
Line 2: "ALM:Y THR:2 RC:5"   // 有无报警 + 限流等级 + BusOff恢复次数
Line 3: "H:15 N:64 BLK:1"    // FIFO_H/N积压数 + 黑名单节点数
Line 4: "RX:12.3K OV:0   "   // 总接收帧数 + FIFO_HIGH溢出次数
```

- 按 KEY 切换页面，`OLED_Clear()` 防画面残留
- 每行填充 16 字符，消除 OLED 像素残影

## 四、报文升降级机制

### 4.1 升级规则

| 触发条件 | 原优先级 | 新优先级 | 升级帧 ID 映射 |
|---|---|---|---|
| DHT11 温度 > 85°C 或 < -20°C | 1 → 0 | ID 0x200→0x100 |
| DHT11 连续 3 次读取失败（传感器断线） | 1 → 0 | ID 0x200→0x100 |
| CAN 错误等级 ≥ 2（被动错误） | 1/2 → 0 | 统一升级 |
| CAN 错误等级 = 3（Bus-Off） | 全部 → 0 | 统一升级 |
| KEY1 手动上报 | — | 0 | 已是紧急帧，不变 |
| **总线负载 ≥ 90%** | — | **禁止升级** | 保护紧急通道不被挤占 |

### 4.2 降级机制

- **自动降级**：升级帧内置 **500ms 超时定时器**（FreeRTOS 软件定时器），超时后传感器/故障条件仍未解除 → 维持 0 级；故障清除 → 切回原优先级
- **手动降级**：KEY2 按下（故障恢复）→ 立即强制降级，取消定时器

### 4.3 升降级裁决流程

```
vTask_CAN_Monitor 每 100ms 执行:
  1. 读取总线负载率
  2. 负载 < 90%: 扫描升级条件 → 判决升级 / 500ms 超时检查 → 判决降级
  3. 负载 ≥ 90%: 冻结所有升级请求，仅维持已有 0 级帧流通
  4. 更新全局状态标志 g_priority_override[]
```

## 五、总线负载自适应限流

### 5.1 负载分级与策略

| 负载区间 | 策略 | 具体动作 |
|---|---|---|
| **< 70%** | 全量上报 | 所有 CAN 帧正常从 FIFO 发送 |
| **70% ~ 90%** | 低频限流 | 光敏（2级）上报周期从 2s 翻倍到 4s；温湿度 + 心跳（1级）不变 |
| **≥ 90%** | 紧急模式 | 仅放行 0 级紧急帧 + 心跳帧（心跳维持节点在线检测）；所有 2 级帧暂停入 FIFO；1 级温湿度降频到 5s |

### 5.2 负载计算

阶段一已有的 100ms 滑动窗口算法保留并增强：
- 窗口大小保持 100ms，统计接收到的 CAN 帧位数
- 加入本机已发送帧位数（从 `vTask_CAN_Tx` 累加），避免仅统计收帧导致低估实际占用
- 结果归一化为 0~10000（0.00%~100.00%）

### 5.3 限流恢复

负载连续 5 个窗口（500ms）低于阈值 5% 以上时恢复下一级：
- 负载从 ≥90% 降到 <85% → 恢复 1 级温湿度正常周期
- 负载从 70%~90% 降到 <65% → 恢复 2 级光敏正常周期

> 滞后区间（5%）防止负载在阈值临界点反复振荡。

## 六、CAN 错误分级处置

### 6.1 错误等级定义（阶段一基础上增强）

| 等级 | 条件 | 处置 |
|---|---|---|
| 0 — 正常 | TEC/REC < 96 | 正常运行，无限制 |
| 1 — 主动错误 | 96 ≤ TEC/REC ≤ 127 | **日志记录**（通过 USART1 输出错误计数），不影响通信 |
| 2 — 被动错误 | 128 ≤ TEC/REC ≤ 255 | **全局限流降频**：所有帧发送间隔 ≥ 50ms；通知上位机 `error_level=2` |
| 3 — Bus-Off | TEC > 255 | **立即复位 CAN 外设**（`CAN_ResetBus()`）+ **清空 FIFO_HIGH 和 FIFO_NORMAL** + 发送紧急故障帧（复位后首帧）+ **清空 TEC/REC 计数器** |

### 6.2 Bus-Off 恢复流程（增强）

阶段一只做了 `CAN_ResetBus()`，阶段二增加：

```
1. 停止 vTask_CAN_Tx（挂起任务）
2. 清空双 FIFO（旧帧在新 CAN 状态下无意义）
3. CAN_ResetBus() 重新初始化
4. 发送 0 级紧急帧（ID 0x100 + 主站节点ID, 功能码 0xF0=BusOff恢复）
5. 恢复 vTask_CAN_Tx
6. 记录 bus_off_recovery_cnt++
```

### 6.3 OLED 错误指示增强

主站 OLED 两页第 1 行均显示 CAN 错误等级：
- `OK`（绿）→ error_level=0
- `WRN`（黄）→ error_level=1，仍在通信但需关注
- `ERR`（红）→ error_level≥2
- `BOF`（红闪）→ Bus-Off 恢复中

Page 2 额外显示总线负载率（`L:12.50%`）、报警标志（`ALM:Y/N`）、限流等级（`THR:0~2`），调试时切至 Page 2 可全面诊断 CAN 总线状态。

## 七、Modbus TCP 断网缓存增强

### 7.1 双区缓存结构

```c
#define HIST_CACHE_MAX 100

typedef struct {
    ModbusRegCache  realtime[20];    // 实时区：当前最新值，覆盖更新
    ModbusRegCache  history[HIST_CACHE_MAX]; // 历史区：环形缓冲，FIFO
    uint8_t         hist_head, hist_tail, hist_count;
    uint32_t        disconnect_start_tick;  // 断网时刻
} ModbusCache;
```

### 7.2 断网分级处理

| 断网时长 | 策略 |
|---|---|
| **< 3s（短断网）** | 保留历史区全部数据，恢复后**批量上传**（每次 TCP 连接上传 20 条/次，直到清空） |
| **≥ 3s（长断网）** | **清空历史区 2 级低频数据**（光敏），仅保留 0 级紧急 + 1 级心跳/温湿度 |
| **历史区溢出（>100条）** | 自动丢弃最旧记录（FIFO 环形覆盖） |

### 7.3 断网检测

- W5500 链路状态轮询（100ms 周期，复用 vTask_CAN_Monitor）
- `LinkUp() == false` 持续 500ms 以上判定为断网
- 恢复后 `LinkUp() == true` 触发批量上传

### 7.4 Modbus 寄存器扩展

在阶段一寄存器基础上新增：

```
寄存器地址    内容                    说明
0x0020       光敏值（lux）           从站 BH1750
0x0021       FIFO_HIGH 使用数       诊断用
0x0022       FIFO_NORMAL 使用数      诊断用
0x0023       FIFO_HIGH 溢出次数      诊断用
0x0024       FIFO_NORMAL 溢出次数    诊断用
0x0025       Bus-Off 恢复次数        诊断用
0x0026       历史缓存条数            断网恢复中的待上传量
0x0027       系统运行时间（秒高位）    uint32 拆分为两个寄存器
0x0028       系统运行时间（秒低位）
0x0029       当前限流等级            0=正常, 1=低频限流, 2=紧急模式
```

## 八、从站传感器扩展与本地容错

### 8.1 BH1750 光敏采集（2级低频任务）

- **初始化**：BH1750_Init()，写 0x10 命令（连续高分辨率模式）
- **采集流程**：每 2s 读取 2 字节光照值，封装为 2 级低频 CAN 帧（ID 0x300 + 节点ID）
- **数据格式**：Byte[3..4] = 光照值（uint16，单位 lux），Byte[5..6] = 保留

### 8.2 从站 FreeRTOS 任务分配

| 任务 | 优先级 | 栈深度 | 周期 | 职责 |
|---|---|---|---|---|
| `vTask_Sensor` | 3 | 256 | DHT11 2s / BH1750 2s | 传感器采集 + 数据缓存 |
| `vTask_CAN_Slave` | 2 | 256 | 事件驱动 | CAN 收发、心跳 500ms |
| `vTask_Key` | 1 | 128 | 20ms 轮询 | 按键扫描 + 消抖 |
| `vTask_Housekeep` | 0 | 128 | 1s | 看门狗、本地缓存管理 |

### 8.3 本地缓存容错

CAN 通信异常时（连续 3 次心跳无 ACK 或 CAN 发送失败），从站本地缓存采集数据：

```c
#define LOCAL_CACHE_MAX 50

typedef struct {
    uint8_t  data[8];   // CAN 帧 8 字节
    uint32_t timestamp; // 采集时刻（SysTick）
} LocalCacheEntry;
```

- 缓存上限 50 条，超出后丢弃最旧数据
- CAN 恢复后批量补传（每 200ms 发送一条历史帧，避免瞬间冲击总线）
- 补传完成后清空缓存

### 8.4 从站 OLED 精简适配（4×16 字符限制）

```
Line 1: "S:Node#01 Ready"       // 节点ID + DHT11状态
Line 2: "T:25.3C L:610   "     // 温度 + BH1750光感（<1000 显示 lux）
Line 3: "H:62.1% C:OK    "     // 湿度 + CAN连接状态
Line 4: "TX:00036 C:00/50 "    // TX帧计数 + 本地缓存使用量
```

光感值自动量程：
| 实际 lux | OLED 显示 | 说明 |
|----------|-----------|------|
| 0 | `L:  0` | 全暗 |
| 610 | `L:610` | 室内正常光照 |
| 1234 | `L:1.2k` | ≥1000 自动切 k-lux |
| 65535 | `L:65.5k` | BH1750 最大值 |

> 显示格式：`"T:%u.%uC L:%3u"`（lux）或 `"T:%u.%uC L:%u.%uk"`（k-lux），每行末尾用空格填充至 16 字符，防止 OLED 像素残影。

## 九、软件架构总览（阶段二）

### 9.1 主站 FreeRTOS 任务图

```
ISR: CAN1_RX0 (最高硬件优先级, 抢占所有任务)
  │
  └─ Binary Semaphore ──→ vTask_CAN_Rx (优先级5)  ──→ FIFO_HIGH / FIFO_NORMAL
                                                        │
vTask_CAN_Monitor (优先级4, 100ms)  ←───────────────────┘
  ├─ 总线负载计算 + 限流裁决
  ├─ TEC/REC 错误分级
  └─ 升降级判决
                                                        │
                              ┌─────────────────────────┘
                              ↓
                       vTask_CAN_Tx (优先级3)
                         └─ 从 FIFO 取帧 → CAN 发送

vTask_Protocol (优先级2, 50ms)
  ├─ CAN → Modbus 寄存器同步
  ├─ 双区缓存管理
  └─ 断网恢复批量上传逻辑

vTask_W5500 (优先级1, 事件驱动)
  ├─ TCP Server 轮询
  └─ Modbus 请求/响应处理

vTask_Housekeep (优先级0, 1s)
  ├─ IWDG 喂狗
  ├─ 任务栈溢出检测
  └─ 故障日志输出 (USART1)
```

### 9.2 从站 FreeRTOS 任务图

```
vTask_Sensor (优先级3)
  ├─ DHT11 采集 (2s)
  ├─ BH1750 采集 (2s)
  └─ 本地缓存写入

vTask_CAN_Slave (优先级2)
  ├─ 心跳发送 (500ms)
  ├─ 传感器帧发送
  ├─ CAN 异常检测
  └─ 恢复后批量补传

vTask_Key (优先级1, 20ms)
  └─ KEY1/KEY2 事件检测

vTask_Housekeep (优先级0, 1s)
  └─ IWDG + 缓存管理
```

## 十、阶段二验收标准

| 序号 | 验收项 | 标准 | 验证方法 |
|---|---|---|---|
| 1 | FreeRTOS 正常运行 | 6 个任务全部调度，SysTick 1ms 节拍，无 HardFault | USART1 输出任务心跳计数 |
| 2 | 双 FIFO 读写正确 | FIFO_HIGH 不溢出（紧急帧<16），FIFO_NORMAL 溢出遵循丢弃策略 | 模拟大量 CAN 帧冲击，ModbusPoll 读溢出计数器 |
| 3 | 报文升级 | DHT11 断线/超温 → 1 级帧升级为 0 级，主站 OLED 显示 ALM | 拔掉 DHT11 / 热风枪加热 |
| 4 | 报文降级 | 500ms 自动降级 + KEY2 手动降级均生效 | KEY2 按下后 ALM 消失 |
| 5 | 总线负载限流 | 负载 <70% 全量、70-90% 光敏翻倍、≥90% 仅紧急+心跳 | CAN 分析仪模拟负载，ModbusPoll 读限流等级 |
| 6 | CAN 被动错误限流 | TEC>127 时帧间隔 ≥50ms | ModbusPoll 读 error_level，示波器测 CAN 帧间隔 |
| 7 | Bus-Off 自动恢复 | TEC>255 → 自动复位 CAN + 清 FIFO + 发紧急帧 | 模拟 CAN 总线短路后恢复正常 |
| 8 | Modbus 短断网恢复 | 断网 <3s → 恢复后批量上传历史数据 | 拔网线 2s 后插回，PC 端验证数据补传 |
| 9 | Modbus 长断网清空 | 断网 ≥3s → 清空 2 级低频数据 | 拔网线 5s 后插回，验证光敏历史被清空 |
| 10 | 光敏传感器采集 | BH1750 每 2s 上报光照值，主站 OLED + ModbusPoll 可读 | ModbusPoll 读 0x0020 寄存器 |
| 11 | 从站本地缓存容错 | CAN 断线 → 本地缓存采集数据 → 恢复后批量补传 | 拔 CAN 线 10s 后恢复，验证补传数据完整性 |
| 12 | OLED 显示完整 | 主站/从站 4×16 布局更新后内容正确 | 目视检查 + 数据一致性比对 |
| 13 | 栈溢出监控 | vTask_Housekeep 检测所有任务栈高水位 > 20% 剩余 | USART1 输出栈统计 |
| 14 | 看门狗 | IWDG 1s 超时，正常运行时永不复位 | 故意死循环验证复位 |

## 十一、踩坑预判（阶段一教训回顾）

| # | 预判风险点 | 预防措施 |
|---|---|---|
| 1 | FreeRTOS SysTick 与 Delay_us() 冲突 | 微秒延时用 DWT 时钟周期计数器避免抢占 SysTick |
| 2 | BH1750 I2C 地址冲突 | ADDR 引脚接地 → 0x23，OLED=0x78，不冲突 |
| 3 | 从站 I2C 总线挂两个设备 | 软件 I2C 无仲裁，两个设备直接用同一组函数，注意 SDA 方向切换 |
| 4 | FreeRTOS 堆栈不足 → HardFault | 先用大栈（512），稳定后根据 `uxTaskGetStackHighWaterMark()` 缩减 |
| 5 | FIFO 互斥锁死锁 | 统一加锁顺序：先 HIGH 后 NORMAL，禁止嵌套反向加锁 |
| 6 | 中断信号量唤醒延迟 | CAN Rx ISR 用 `portYIELD_FROM_ISR` 确保立即任务切换 |
| 7 | W5500 SPI 在 FreeRTOS 下被抢占 | `vTask_W5500` SPI 操作期间禁止任务切换（临界区保护 SPI 帧完整性） |
| 8 | DWT 周期计数器不可用 | 某些 STM32F103 需在 `CoreDebug->DEMCR |= 0x01000000` 后才能用 DWT |

## 十三、阶段二与阶段一的关系

```
阶段一（已完成）                阶段二（本次）
```
